# Cryptocurrency Outlook — ユーザーガイド

## 概要

Cryptocurrency Outlookは、Binance Futuresのリアルタイムデータを用いて暗号通貨のテクニカル分析を自動実行し、売買シグナルを生成するWebアプリケーションです。

**データソース:** Binance Futures（認証不要の公開API）
**注意:** 本ツールは投資助言ではありません。投資判断はご自身の責任でお願いします。

---

## 画面構成

### 表示モード

画面上部のトグルで3つの表示モードを切り替えられます。

| モード | 説明 |
|--------|------|
| **簡易版** | 結論とPR比較のみ表示。素早く判断したいとき向け |
| **詳細版** | テクニカル指標、パターン、デリバティブなど全データを表示 |
| **ダッシュボード** | 全情報を一画面に配置。通常運用向け（デフォルト） |

### テーマ

右上の丸ボタンで6種類のテーマに切り替えられます。

- 黒（デフォルト）/ 白 / やさしい / 淡い青 / 桜色 / 淡いオレンジ

---

## 基本操作

### 1. 銘柄を選択

- テキストボックスにBinance Futuresのシンボルを入力（例: `BTCUSDT`）
- クイックボタンで人気銘柄をワンタップ選択：BTCUSDT / ETHUSDT / SOLUSDT / XRPUSDT / DOGEUSDT

### 2. 時間足を選択（複数選択可）

| 時間足 | 用途 |
|--------|------|
| **5分足** | 超短期（数分〜1時間） |
| **15分足** | デイトレード |
| **1時間足** | デイトレード |
| **4時間足** | デイトレード〜スイング |
| **日足** | スイング（数日） |

**推奨組み合わせ：**
- 超短期: 5分足 + 15分足
- デイトレード: 15分足 + 1時間足 + 4時間足
- スイング: 1時間足 + 4時間足 + 日足

### 3. 「分析開始」をクリック

Binance APIからデータを取得し、テクニカル分析を自動実行します。

---

## 分析結果の見方

### 結論（シグナル）

分析結果は4種類のシグナルで表示されます。

| シグナル | 意味 | 条件 |
|----------|------|------|
| 🟢 **ロングエントリー推奨** | 買い方向のシグナルが優勢 | 強気スコア - 弱気スコア ≥ 2 かつ RR比 ≥ 1.5 |
| 🔴 **ショートエントリー推奨** | 売り方向のシグナルが優勢 | 弱気スコア - 強気スコア ≥ 2 かつ RR比 ≥ 1.5 |
| 🟡 **引きつけて待機** | 方向性はあるがエントリーには不十分 | スコア差 < 2 または RR比 < 1.5 |
| ⚪ **見送り推奨** | シグナルが拮抗して方向性がない | 強気/弱気のスコア差 < 1 |

### PR比較（Long vs Short）

ロングとショートの両プランを並べて比較できます。

- **エントリー価格** — 推奨される参入価格
- **損切り（SL）** — ストップロス価格とリスク率（%）
- **利確（TP）** — テイクプロフィット価格とリワード率（%）
- **RR比** — リスクリワード比率（1.5以上が推奨）

### 信頼度スコア

0〜100のスコアで分析の信頼度を表します。時間足の一致度、トレンド強度、デリバティブデータなどから算出されます。

## 分析に使用されるデータ

### テクニカル指標

各時間足で以下の指標を計算し、加重スコアリングに使用します。

| 指標 | 説明 |
|------|------|
| RSI (14) | 相対力指数。30以下で買われすぎ、70以上で売られすぎ |
| MACD (12/26/9) | トレンドの方向と勢い |
| SMA (20/50/200) | 単純移動平均線 |
| EMA (9/21) | 指数移動平均線 |
| ボリンジャーバンド | 価格の上限/下限バンドからの乖離 |
| ストキャスティクスRSI | RSIのオシレーター。20以下/80以上で反転示唆 |
| ADX | トレンドの強さ（方向性指数） |
| ATR | 平均的な価格変動幅（ボラティリティ） |

### デリバティブデータ

| データ | 説明 |
|--------|------|
| OI（未決済建玉） | ポジション量の変化で新規参入/解消を判断 |
| ファンディングレート | プラス＝ロング過多、マイナス＝ショート過多 |
| ファンディングトレンド | 過熱状態の検知（連続的な偏り） |
| プレミアムインデックス | 先物と現物の乖離率 |
| トップトレーダーの売買比率 | 大口トレーダーのポジション傾向 |

### その他の分析要素

| 要素 | 説明 |
|------|------|
| パターン認識 | ダブルトップ/ボトム、エンガルフィング等のチャートパターン |
| ダイバージェンス | 価格と指標の乖離（通常/ヒドゥン） |
| 出来高プロファイル (VRVP) | バリューエリア、POC（最大出来高価格帯）の分析 |
| オーダーフロー | テイカー売買比率から買い/売り圧力を分析 |
| 偽ブレイクアウト | サポート/レジスタンスの偽のブレイクを検知 |
| 出来高スパイク | 異常な出来高急増の検知 |
| マーケットレジーム | トレンド/レンジ/高ボラティリティの判定 |
| 清算マップ | 清算が集中する価格帯の推定 |

## 外部データ連携

### Fear & Greed Index（恐怖・強欲指数）

市場のセンチメントを0〜100で表示。極端な恐怖/強欲はコントラリアン（逆張り）シグナルとして活用されます。

### 経済指標カレンダー

FOMC、CPI、雇用統計などの重要経済指標の発表スケジュールを表示。

- 🟢 通常 — 影響なし
- 🟡 注意 — 中程度の経済指標が控えている
- 🔴 危険 — 重要経済指標の発表が間近。エントリーシグナルが出ても**自動的にwait（様子見）に変更**されます

**必要なAPIキー:** Finnhub（無料） — `FINNHUB_API_KEY`

### ニュース

地政学リスクや規制ニュースをリアルタイムで取得・分析。

- 各記事に**影響度**（高/中/低）と**関連度スコア**（1〜10）を付与
- 高影響リスクオフニュースが3件以上 → ロングエントリーが自動的に**wait**に変更
- ニュースのセンチメント（リスクオン/リスクオフ）がスコアリングに反映

**APIキー不要** — RSSフィード（CoinTelegraph、SEC、FRB等）から自動取得

## 売買シミュレーター

分析結果に基づいて仮想的なポジションを作成・管理できます。

### 操作方法

1. **方向を選択** — ロング / ショート
2. **投資金額を入力** — USDT建て
3. **レバレッジを設定** — 1x〜125x
4. **エントリー/SL/TP価格をカスタマイズ**（任意）— 分析結果の推奨値がデフォルトで入力済み
5. **「ポジションを保存」をクリック**

### ポジション管理

保存したポジションは3つの状態で管理されます。

| 状態 | 説明 |
|------|------|
| **待機中（Pending）** | エントリー価格に到達待ち |
| **オープン（Open）** | 約定済み。リアルタイムで損益を表示 |
| **クローズ（Closed）** | 決済済み。損益結果を表示 |

- **約定** — 現在価格でポジションをオープンに変更
- **決済** — 手動決済 / 損切り / 利確 / 時間決済を選択
- ポジションデータはブラウザのlocalStorageに保存されます

## コピペ用プロンプト（詳細版のみ）

分析結果のテクニカルデータを構造化したプロンプトを自動生成します。

**使い方：**
1. 詳細版で分析を実行
2. 「コピペ用プロンプト」セクションの「コピー」ボタンをクリック
3. ChatGPT等のAIチャットに貼り付けて、さらに深い分析を依頼

## 分析履歴

- 分析を実行するたびに自動的に履歴を保存（最大100件）
- 過去の分析結果を呼び出して再表示可能
- エクスポート/インポート機能で履歴のバックアップが可能

## Telegram通知

### シグナル通知

外部cronサービスで `/api/analyze` を定期実行し、エントリーシグナル発生時にTelegramへ通知します。

**通知条件：**
- `enter_long`（ロングエントリー推奨）のとき
- `enter_short`（ショートエントリー推奨）のとき
- `wait` / `skip` は通知されません（`TELEGRAM_NOTIFY_ALL=true` で全通知可能）

**通知内容：**
- シグナル（ロング/ショート）と銘柄
- 現在価格と24時間変動率
- 信頼度スコア
- エントリー/損切り/利確の価格
- RR比
- トレンド方向と時間足
- ファンディングレート
- 関連ニュース（あれば）
- 経済指標の警告（あれば）
- 結論の理由

### ニュース通知

5分ごとに新着ニュースをチェックし、中〜高影響度の記事をTelegramに通知します。

- リンクベースの重複チェックにより、同じ記事は2回通知されません
- デプロイ後にリセットされます

---

## 環境変数

| 変数名 | 必須 | 説明 |
|--------|------|------|
| `TELEGRAM_BOT_TOKEN` | 通知に必要 | Telegram BotFatherから取得するBOTトークン |
| `TELEGRAM_CHAT_ID` | 通知に必要 | 通知先のTelegramチャットID |
| `TELEGRAM_NOTIFY_ALL` | 任意 | `true` にすると wait/skip でも通知 |
| `FINNHUB_API_KEY` | 任意 | Finnhub APIキー（経済指標カレンダー用） |

## APIエンドポイント

| エンドポイント | メソッド | 説明 |
|----------------|----------|------|
| `/api/analyze` | GET | メインの分析API。`symbol` と `timeframes` パラメータが必要 |
| `/api/news` | GET | ニュース記事を取得 |
| `/api/news-notify` | GET | ニュース取得 + Telegram通知（cronで5分ごとに実行） |
| `/api/economic-calendar` | GET | 経済指標カレンダーを取得 |
| `/api/refresh-external` | GET | Fear&Greed + 経済カレンダーのキャッシュ更新（cronで30分ごとに実行） |
| `/api/ai-analyze` | POST | AIによる追加分析（将来用） |

### 分析API の使用例

```
GET /api/analyze?symbol=BTCUSDT&timeframes=15m,1h,4h
```

有効な時間足: `5m`, `15m`, `1h`, `4h`, `1d`

## スコアリングの仕組み

### 時間足の重み

長い時間足ほど重みが大きく、シグナルに強く影響します。

| 時間足 | 重み |
|--------|------|
| 5分足 | 1.0 |
| 15分足 | 1.5 |
| 1時間足 | 2.0 |
| 4時間足 | 3.0 |
| 日足 | 4.0 |

### シグナル判定フロー

```
1. 各時間足のテクニカル指標を加重スコアリング
   → bullishScore（強気）/ bearishScore（弱気）を算出

2. デリバティブデータによるスコア補正
   → OI変化、ファンディングレート、過熱状態

3. 追加要素のスコア補正
   → 階層分析、オーダーフロー、センチメント、ニュース

4. diff = bullishScore - bearishScore で判定
   → |diff| < 1        → skip（見送り）
   → RR比 < 1.5        → wait（待機）
   → diff >= 2          → enter_long（ロング推奨）
   → diff <= -2         → enter_short（ショート推奨）
   → それ以外           → wait（待機）

5. オーバーライド（上書き）
   → リスクオフニュース3件以上: enter_long → wait
   → 重要経済指標間近: enter_long/enter_short → wait
```

## トラブルシューティング

| 症状 | 対処 |
|------|------|
| Telegram通知が来ない | 環境変数の設定確認 → Redeployしたか確認 → `/api/analyze` のレスポンスで `_telegram.notified` を確認 |
| ニュース通知が来ない | `/api/news-notify` を直接叩いて `notified` の値を確認。デプロイ直後は重複チェック用のSetがリセットされるため初回は通知される |
| 経済カレンダーが表示されない | `FINNHUB_API_KEY` が設定されているか確認 |
| ニュースが表示されない | RSSフィードの取得状況をサーバーログで確認 |
| 分析が遅い | 選択する時間足が多いほどAPI呼び出しが増えて遅くなります |
| cronが動いていない | cron-job.org のStatisticsタブでHTTPステータスコードを確認（200なら正常） |
